# 05 · 协议与数据参考

版本 v0.2 · 2026-10-15

> **使用警示**：本章涉及具体协议字节/编码的条目**必须**带标注。凡我无法给出可信来源的（尤其 Apple Continuity 子类型编码），标 [GUESS] 或 [待验证]，**开发时以实测和权威资料为准，不得直接采信本文数字**。

---

## 1. BLE 广播基础

- [KNOWN, HIGH] 广播数据（AD）由若干 AD 结构组成，每个结构 = `[长度][类型][值...]`，长度字节含类型字节本身，不含长度字节。
- [KNOWN, HIGH] 单包 legacy 广播数据上限 31 字节；扩展广播可突破。
- [KNOWN, HIGH] 扫描响应（SCAN_RSP）由被动扫描时设备对 SCAN_REQ 的回应，或主动扫描时请求返回。

## 2. 关键 AD Type（供 F3 解析器对照）

| AD Type | 含义 | 本工程用途 |
|---|---|---|
| 0x01 | Flags | 输出 `flags` |
| 0x02/0x03 | 16-bit 服务 UUID（不完整/完整） | P2 输出 `svc` |
| 0x06/0x07 | 128-bit 服务 UUID | P2 |
| 0x08 | 缩短本地名 | 输出 `name` |
| 0x09 | 完整本地名 | 输出 `name` |
| 0x0A | TX Power Level | 输出 `tx` |
| 0x16 | Service Data 16-bit UUID | P2 |
| 0xFF | Manufacturer Specific Data | 输出 `co`（厂商 ID） |

[KNOWN, HIGH] 以上 AD type 编号为标准值。

## 3. 厂商识别

- [KNOWN, HIGH] AD type 0xFF 结构：前 2 字节 = Bluetooth SIG 16-bit Company ID（小端），其后为厂商自定义数据。
- [KNOWN, HIGH] Apple 的 Company ID = **0x004C (76)**。
- [KNOWN, HIGH] Company ID 可被任意伪造，扫描到 0x004C **不等于**该设备是 Apple。输出措辞用"自述为 Apple"。
- [KNOWN, MED] 完整 Company ID 分配表见 Bluetooth SIG Assigned Numbers 文档；生成方式见 O6。

## 4. Apple Continuity（子类型识别，F6）

- [KNOWN, MED] Apple 在 0xFF / 0x004C 载荷中，首字节为 Continuity 消息类型；含 iBeacon、AirDrop、AirPods 配对、Handoff、Nearby Info、Find My 等类别。
- **[GUESS, LOW] 各子类型的具体字节值：调试版实现见 `main/identify/apple.c`（`subtype_by_first_byte`）。** 该表来自公开逆向社区资料，**未在本机验证，可能不完整/不准确**。P3 必须以实测抓包 + 权威 Assigned Numbers / 逆向资料校准后才能信任（O3）。调试版还包含一个 Nearby/Handoff 长度前缀的启发式判断，同样待验证。
- **本文与代码不给出可担保的权威字节值。** 实测是唯一可信来源。

## 5. 追踪器特征（F7）

- [KNOWN, MED] Find My 网络相关广播、Tile、Samsung SmartTag 各有签名特征。具体签名同样需 P3 实测/权威资料确认，本文不列具体字节。

## 6. 输出 Schema（P2 起：5s 周期设备快照）

每 5 秒一个批次：先一行摘要，随后每设备一行。全部为单行 JSON。

**摘要行**：
| 字段 | 类型 | 含义 |
|---|---|---|
| `snap` | bool | 恒 true，标识摘要行 |
| `devices` | int | 表中设备总数（含暂隐藏的）|
| `shown` | int | 本批次实际打印的设备数（最近在场）|
| `hidden` | int | 因超过打印过滤窗口而未打印的设备数 |
| `evt` | int | 累计 GAP 事件数 |
| `disc` | int | 累计广播上报数 |
| `scanrsp` | int | 累计 SCAN_RSP 数（主动扫描时 >0 即生效）|
| `period_ms` | int | 快照周期 |

**打印过滤**：仅打印 `age_ms ≤ PRINT_RECENT_MS`（默认 30s）的设备，抑制僵尸条目。阈值在 `main/main.c` 顶部宏。

**设备行**：
| 字段 | 类型 | 含义 |
|---|---|---|
| `dev` | bool | 恒 true，标识设备行 |
| `key` | string | 身份键类型：`addr`（按 MAC）或 `fmkey`（按 FindMy 公钥，F14）|
| `addr` | string | 最近所见源地址 "aa:bb:…"（轮换 MAC 会变）|
| `at` | int | 地址类型 |
| `co` | int | 主身份厂商 ID（-1 = 无）；主身份优先级 真厂商>0x004C>无 |
| `vendor` | string | 厂商名（查 SIG 表）|
| `name` | string | 本地名（已 JSON 转义）|
| `subtype` | string | Apple Continuity 子类型名 |
| `tracker` | string\|null | 追踪器类别或 null |
| `n` | int | 观测次数 |
| `rssi` | int | 最近 RSSI；`rmin`/`rmax` 为最小/最大 |
| `age_ms` | int | 距最近一次观测的毫秒（非负）|
| `life_ms` | int | 从首次出现至今毫秒；**按 MAC 键时受地址轮换影响，按 fmkey 键时稳定** |
| `near_persist` | bool | **信息项，非告警**：追踪器类设备持续近距。普通 Apple 设备也会为 true（见 docs/06 R9），**不代表被跟踪** |

**逐包原始输出**：把 `main/main.c` 顶部 `EMIT_RAW_PER_PACKET` 设为 1 会额外打印每包一行（字段同 P1），量大，仅调试用。


### 6.2 串口争用（P1 已知，已缓解）
[KNOWN, HIGH] 日志与抓包共用同一串口，ESP_LOG 行会插入 NDJSON 流中。当前 `sdkconfig.defaults` 已设 `CONFIG_LOG_DEFAULT_LEVEL_NONE=y` 静默日志；代码中把非必要日志降为 DEBUG 级。若日后需要用日志排障，请把 NDJSON 与日志分到不同串口，或解析时按行过滤。
